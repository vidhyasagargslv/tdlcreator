# TDL Maker v0.3
Offline HTML tool (`index.html`, double-click) that generates a TallyPrime `.tdl` for syncing with your backend.
Load via **F1 > TDL & Add-On > Manage Local TDLs**. **Nothing here has been verified on a real TallyPrime yet – follow [TESTING.md](TESTING.md).**

## Modes
- **Core sync (recommended, default):** Sales Orders, Purchase Orders, Groups, Ledgers/Parties, Units, Godowns, Stock Groups, Stock Items, Closing Stock. Push + pull. Generated by `core.js` using only documented TDL patterns.
- **Advanced:** every option from v0.2 (`gen.js`), more experimental.

## Core sync – how it works
| Feature | How | Confidence |
|---|---|---|
| Menu, config screen, date range (persistent variables) | `[#Menu]`, `[Variable] Persistent: Yes`, `Modifies:` | High (documented) |
| Push | `HTTP Request: url: POST: XML: ASCII: <Request Report>: <post function>` | High (documented) |
| Success detection | post function walks `Parameter Collection`, reads `$Status` | High (documented example) |
| Incremental push | max AlterID computed before send, saved **only when STATUS=1**; "Reset marks" key | Medium (logic is ours) |
| Auth header / Basic | `Export Header` on request report / remote collection | High (documented) |
| Push detail SO/PO | header, `AllInventoryEntries` (qty, rate, discount, amount, GST rate) → `BatchAllocations` (godown, batch, order no, due date) + `AccountingAllocations`, `LedgerEntries` | Medium: method names `$OrderDueDate`, `$GSTRate`, `$PlaceOfSupply` unverified |
| Push masters | ledger (parent, GSTIN, state, address, pincode, email, mobile, opening/closing), stock item (group, category, unit, GST applicable, HSN, opening/closing qty/rate/value), groups, units, godowns, stock groups | Medium: `$GSTDetails[Last].HSNCode`, `$LedgerMobile`, `$LedgerContact` unverified |
| Closing stock | Stock Item `$ClosingBalance/$ClosingRate/$ClosingValue` | Medium |
| Pull masters | `Remote URL` + `XMLObjectPath` collection, `New Object: <Type>: $NAME: Yes` (create **or alter** by name) + `Set Value` + `Save Target` | High pattern / Medium field names |
| Pull vouchers SO/PO | flat VOUCHER/ITEM/TAX rows; `New Object: Voucher`, `Insert Collection Object` for LedgerEntries / AllInventoryEntries / BatchAllocations / AccountingAllocations, `$$TgtObject` for qty/rate | Medium-Low: sign conventions and order fields need real-Tally check |
| Duplicates | masters: alter by name; vouchers: skipped if same number + type exists | Medium |
| Counts | created / altered / skipped / errors via `$$LastResult` after `Save Target` | Medium (`$$LastResult` unverified) |
| Company gate (name) | `$$IsEqual:##SVCurrentCompany:...` | High; GSTIN variant low |

## Backend contract (Core sync)
Base URL = Configuration → Base URL (e.g. `http://192.168.1.10:8787`).

### Push: `POST {base}/push/{entity}`
Entities: `groups ledgers units godowns stockgroups stockitems closingstock salesorders purchaseorders`. Header `x-api-key` (or Basic / `?apikey=` / `<APIKEY>` per option). Body ASCII XML:
```xml
<ENVELOPE>
 <HEADER><ENTITY>salesorders</ENTITY><COMPANY>ACME</COMPANY><COMPANYNAME>ACME Pvt Ltd</COMPANYNAME><FROMDATE>20261001</FROMDATE><TODATE>20261031</TODATE><COUNT>1</COUNT></HEADER>
 <VOUCHER><DATE>20261027</DATE><VOUCHERTYPE>Sales Order</VOUCHERTYPE><VOUCHERNUMBER>SO-1</VOUCHERNUMBER><REFERENCE>PO-77</REFERENCE>
  <PARTYNAME>Customer A</PARTYNAME><PARTYGSTIN>29AAA...</PARTYGSTIN><PLACEOFSUPPLY>Karnataka</PLACEOFSUPPLY><NARRATION/><TOTAL>-1180</TOTAL>
  <GUID>..</GUID><MASTERID>12</MASTERID><ALTERID>345</ALTERID>
  <INVENTORYENTRY><STOCKITEM>Widget</STOCKITEM><QTY>10</QTY><ACTUALQTY>10</ACTUALQTY><RATE>100</RATE><DISCOUNT>0</DISCOUNT><AMOUNT>1000</AMOUNT><GSTRATE>18</GSTRATE>
   <BATCH><GODOWN>Main Location</GODOWN><BATCH>Primary Batch</BATCH><ORDERNO>SO-1</ORDERNO><DUEDATE>20261105</DUEDATE><QTY>10</QTY><AMOUNT>1000</AMOUNT></BATCH>
   <ACCOUNTINGALLOCATION><LEDGERNAME>Sales 18%</LEDGERNAME><AMOUNT>1000</AMOUNT></ACCOUNTINGALLOCATION>
  </INVENTORYENTRY>
  <LEDGERENTRY><LEDGERNAME>Customer A</LEDGERNAME><AMOUNT>-1180</AMOUNT><ISPARTY>Yes</ISPARTY></LEDGERENTRY>
  <LEDGERENTRY><LEDGERNAME>CGST</LEDGERNAME><AMOUNT>90</AMOUNT><ISPARTY>No</ISPARTY></LEDGERENTRY>
 </VOUCHER>
</ENVELOPE>
```
Masters use `<GROUP>`, `<LEDGER>`, `<UNIT>`, `<GODOWN>`, `<STOCKGROUP>`, `<STOCKITEM>` rows (fields listed in `core.js` `MF`). Amounts: Tally sign (negative = debit). Dates `YYYYMMDD`. Upsert by GUID.

**Reply (required):** `<ENVELOPE><STATUS>1</STATUS></ENVELOPE>` = success; anything else = failure (nothing is marked synced). Reply HTTP 200.

### Pull: `GET {base}/pull/{entity}`
Entities: `groups units godowns stockgroups ledgers stockitems salesorders purchaseorders`. Pull ALL runs in this dependency order.
```xml
<ENVELOPE><GROUP><NAME>Mock Customers</NAME><PARENT>Sundry Debtors</PARENT></GROUP></ENVELOPE>
<ENVELOPE><UNIT><NAME>Nos</NAME><FORMALNAME>Numbers</FORMALNAME><DECIMALPLACES>0</DECIMALPLACES></UNIT></ENVELOPE>
<ENVELOPE><GODOWN><NAME>Warehouse</NAME><PARENT/></GODOWN></ENVELOPE>
<ENVELOPE><STOCKGROUP><NAME>Finished Goods</NAME><PARENT/></STOCKGROUP></ENVELOPE>
<ENVELOPE><LEDGER><NAME>Customer A</NAME><PARENT>Sundry Debtors</PARENT><GSTIN/><STATE/><COUNTRY/><PINCODE/><EMAIL/><MOBILE/><ADDRESS1/><ADDRESS2/><OPENINGBALANCE/></LEDGER></ENVELOPE>
<ENVELOPE><STOCKITEM><NAME>Widget</NAME><PARENT>Finished Goods</PARENT><CATEGORY/><BASEUNITS>Nos</BASEUNITS><HSNCODE/><GSTRATE/><OPENINGQTY/><OPENINGRATE/><OPENINGVALUE/></STOCKITEM></ENVELOPE>
```
Orders (flat, linked by VOUCHERNUMBER; all amounts **positive**, TDL applies signs; TOTAL = items + taxes):
```xml
<ENVELOPE>
 <VOUCHER><VOUCHERNUMBER>SO-1</VOUCHERNUMBER><DATE>20261027</DATE><PARTYNAME>Customer A</PARTYNAME><REFERENCE/><NARRATION/><TOTAL>1180</TOTAL></VOUCHER>
 <ITEM><VOUCHERNUMBER>SO-1</VOUCHERNUMBER><STOCKITEM>Widget</STOCKITEM><QTY>10</QTY><RATE>100</RATE><AMOUNT>1000</AMOUNT><GODOWN/><BATCH/><DUEDATE>20261105</DUEDATE><LEDGER>Sales 18%</LEDGER></ITEM>
 <TAX><VOUCHERNUMBER>SO-1</VOUCHERNUMBER><LEDGERNAME>CGST</LEDGERNAME><AMOUNT>90</AMOUNT></TAX>
</ENVELOPE>
```
Rules: names must match Tally exactly (parents, units, ledgers must exist or be pulled first); empty tags are ignored (do not overwrite); opening balances / addresses are set only when creating; existing order numbers are skipped. Full samples in `tools/mock-server/samples/`.
